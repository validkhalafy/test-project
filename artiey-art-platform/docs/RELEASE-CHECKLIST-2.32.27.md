# چک‌لیست انتشار ۲.۳۲.۲۶

> همهٔ تست‌های خودکار با شبیه‌ساز وردپرس اجرا شده‌اند. موارد زیر باید روی **سایت آزمایشی (staging) با کپی دیتابیس واقعی** انجام شود، نه روی سایت زنده.

## ۱. نقاطی از سیستم که این تغییرات روی آن‌ها اثر می‌گذارند
| تغییر | اثر احتمالی | چه چیزی را ببینید |
|---|---|---|
| فرم ثبت‌نام جدید (نام فیلدها `f[role][field]`، nonce جدید) | هر فرم سفارشی/قالب/Elementor که با فیلدهای قدیمی (`reg_username`، `first_name` …) پست می‌کرد دیگر کار نمی‌کند | همهٔ جاهایی که `[art_coa_register]` یا ویجت ثبت‌نام گذاشته‌اید |
| ورود فقط با ایمیل، نام کاربری تصادفی | کاربری که انتظار نام کاربری قدیمی را دارد؛ افزونه‌هایی که از user_login نمایش می‌دهند | صفحهٔ ورود، آرشیو نویسنده |
| تأیید ایمیل | اگر ایمیل سایت (SMTP) کار نکند ثبت‌نام انجام نمی‌شود | ارسال واقعی ایمیل، پوشهٔ اسپم، SPF/DKIM |
| تأیید مدیر (status=pending) | پروفایل‌ها تا انتشار عمومی نمی‌شوند؛ شمارنده‌ها/آمار ممکن است پروفایل در انتظار را حساب نکنند | آمار عمومی، فهرست‌ها، نقشهٔ سایت، شمارندهٔ داشبورد مدیر |
| بستن wp-admin برای نقش‌های art_* (به‌جز profile.php) | اعضایی که قبلاً از wp-admin استفاده می‌کردند؛ افزونه‌هایی که برای این نقش‌ها صفحهٔ ادمین دارند | ورود با هر ۵ نقش |
| محدودیت نرخ ثبت‌نام ۵ → ۱۲ در ساعت | تغییر رفتار ضداسپم | رفتار پشت NAT/دفتر |
| پاک‌سازی روزانهٔ حساب‌های تأییدنشده (۷ روز) | حذف حساب‌هایی که فقط نقش art_* دارند | cron روی میزبان |
| تبدیل اسلاگ | آدرس‌های جدید لاتین؛ قدیمی‌ها با SlugHistory ریدایرکت می‌شوند | ویرایش اسلاگ در ویرایشگر بلوکی و کلاسیک، سبک هنری |
| سایت‌مپ تصویری | سایت‌مپ تکراری اگر افزونهٔ سئو فعال باشد (خودکار غیرفعال می‌شود) | `/art-image-sitemap.xml`، robots.txt |
| ساخت صفحات خودکار | صفحه‌های جدید با نامک `art-*` | منوی «ساخت صفحات»، تداخل با صفحات موجود |
| کنترل کش صفحه | صفحه‌های دارای فرم/حراج در کش صفحه ذخیره نمی‌شوند؛ نمرهٔ کش در Site Health برای صفحه‌ای که این شورت‌کدها را دارد | اگر صفحهٔ اصلی چنین شورت‌کدی دارد |

## ۲. تست‌های دستی قبل از انتشار
**ثبت‌نام و حساب** (برای هر ۵ نقش)
1. ثبت‌نام با داده معتبر ← پیام «ایمیل را بررسی کنید» ← دریافت ایمیل ← کلیک روی لینک در **همان مرورگر** ← ورود عادی.
2. همان لینک در **مرورگر/دستگاه دیگر** ← باید صفحهٔ تعیین رمز جدید بیاید.
3. لینک منقضی (۴۸ ساعت) و کلید اشتباه ← پیام نامعتبر؛ ارسال دوباره ایمیل.
4. ایمیل تکراری ← همان پیام عادی؛ هیچ ایمیل/حسابی ساخته نشود.
5. ارسال سریع (زیر ۳ ثانیه)، honeypot پر، nonce منقضی (فرم را ۱۲+ ساعت باز بگذارید).
6. خرابی عمدی SMTP ← حساب ساخته‌شده حذف شود و کاربر بتواند دوباره تلاش کند.
7. بدون جاوااسکریپت: تعویض نقش با پیوندها؛ با صفحه‌کلید: انتخاب نقش و پیمایش فرم.
8. پس از ثبت‌نام: پروفایل در وردپرس «در انتظار بررسی»؛ پس از انتشار، در سایت و سایت‌مپ دیده شود.

**دسترسی** (دو حساب از دو نقش)
1. حساب A بکوشد با تغییر پارامتر (`entity_id`، `role`، `user_id`) در درخواست ویرایش، پروفایل B را تغییر دهد ← بی‌اثر.
2. حساب عضو به `/wp-admin/` و `/wp-json/wp/v2/users` برود ← ریدایرکت / بدون نشت ایمیل یا نام کاربری.
3. `?author=N` برای کاربران عضو ← نباید نام کاربری حاوی بخشی از ایمیل نشان دهد.
4. مدیری که نقش art_* هم دارد قفل نشود.

**اسلاگ**
1. ویرایشگر بلوکی: اسلاگ فارسی تایپ و ذخیره ← لاتین شود. 2. ویرایشگر کلاسیک و ویرایش سریع. 3. خالی‌کردن اسلاگ. 4. سبک هنری (taxonomy). 5. ذخیرهٔ دوبارهٔ پست قدیمی با اسلاگ فارسی ← آدرس عوض نشود. 6. آدرس قدیمی ← ۳۰۱.

**سئو**
1. `/art-image-sitemap.xml` در Search Console «Sitemaps» ثبت و بدون خطا خوانده شود (با افزونهٔ سئو فعال، نباید ثبت شود).
2. Rich Results Test برای یک گالری (ArtGallery)، نمایشگاه، اثر و هنرمند.
3. صفحهٔ ثبت‌نام: عنوان/توضیح یکتا؛ داشبورد و وضعیت‌های ثبت‌نام `noindex`.

**کش و سرعت**
1. Site Health ← کش صفحه، قبل و بعد.
2. با Query Monitor تعداد کوئری و زمان صفحهٔ اصلی، یک گالری، یک هنرمند با ۱۰۰+ اثر.
3. صفحهٔ ثبت‌نام با افزونهٔ کش فعال ← باید کش نشود.

**بازگشت (rollback)**: نسخهٔ قبلی را جایگزین کنید؛ گزینه‌های `art_coa_member_form`، `artiey_aet_appearance*`، `artiey_aet_pages*` بی‌ضررند. حساب‌های «در انتظار تأیید» ایمیل (متای art_coa_email_pending) را نگه دارید و پس از بازگشت دستی بررسی کنید.

## ۳. چیزهایی که عمداً ساخته نشده
- سایت‌مپ ویدیو/VideoObject: افزونه فیلد ویدیو ندارد؛ باید ابتدا مدل داده افزوده شود.
- سایت‌مپ اخبار (Google News): فقط برای ناشران تأییدشده در Google News معنا دارد.
- ابزار کلمات کلیدی: به داده و API بیرونی (Search Console/ابزارهای پولی) نیاز دارد و داخل افزونه ساختنی نیست.
- IndexNow، hreflang در `<head>`، FAQ schema: ساخته نشد.

## ۴. افزوده‌های ۲.۳۲.۲۷ برای تست دستی
- ثبت‌نام کیوریتور و مجموعه‌دار با «تأیید مدیر» روشن ← پس از تأیید ایمیل، پروفایل در سایت دیده **نشود** ← در «کیوریتورها/مجموعه‌دارها» دکمهٔ «تأیید و انتشار» ← پروفایل و نقشهٔ سایت دیده شود ← «تعلیق» ← دوباره پنهان.
- ایمیل اعلان مدیر: لینک به صفحهٔ تأیید همان نقش باز شود.
- صفحهٔ فراخوان‌ها و «دنبال‌شده‌های من» که از «ساخت صفحات» ساخته شده در مرورگر بررسی ظاهری شود (کارت‌ها، شبکه، موبایل).
