# گزارش کنترل کیفیت — WP COA Pro 1.11.0

## بهینه‌سازی‌های عملکرد در نسخه 1.11.0

- فهرست عمومی پروفایل‌ها و گالری‌ها از projection محدود ستون‌ها استفاده می‌کند؛ فهرست مدیریت پروفایل‌ها نیز دیگر متن کامل زندگی‌نامه، تحصیلات، جوایز و نمایشگاه‌ها را برای حداکثر ۵۰۰ ردیف نمی‌خواند. اگر نمایش خلاصه زندگی‌نامه در شورت‌کد خاموش باشد، ستون‌های زندگی‌نامه اصلاً از دیتابیس خوانده نمی‌شوند.
- آثار ثبت‌شده در صفحه پروفایل، پس از نخستین بررسی امضای HMAC برای ۱۰ دقیقه کش می‌شوند. صدور گواهی، ابطال و انتقال مالکیت نسل این کش را تغییر می‌دهد تا نتیجه بعدی دوباره از منبع بررسی شود.
- فهرست‌های عمومی و شمارنده‌های پروفایل و گالری با کش کوتاه‌مدت سرو می‌شوند و ذخیره/تغییر وضعیت رکوردها کش نسل جدید ایجاد می‌کند. جست‌وجوهای دلخواه و نامک‌های ناموجود در transient ذخیره نمی‌شوند تا ورودی‌های تصادفی عمومی باعث رشد بی‌رویه کلیدهای کش پایگاه داده نشوند.
- فرم پروفایل شناسه پیوست تصویر را جداگانه ذخیره می‌کند تا WordPress بتواند `srcset` و اندازه‌های کوچک‌تر بسازد؛ رکوردهای قدیمی که فقط URL دارند بدون حذف تصویر همچنان نمایش داده می‌شوند و هنگام ذخیره دوباره، در صورت امکان به پیوست رسانه نگاشت می‌شوند.
- در صفحات بدون مؤلفه COA، خواندن تنظیمات برند و تولید CSS درون‌خطی انجام نمی‌شود. اسکن JSON المنتور فقط در صورتی انجام می‌شود که Elementor فعال باشد؛ تشخیص شورت‌کدها نیز به یک اسکن محتوا کاهش یافته است.

## آزمون‌های مخصوص تغییرات عملکرد

- `php -l` برای همه فایل‌های PHP؛ `node --check` برای فایل‌های JavaScript. آزمون محلی شبیه‌سازی‌شده تأیید می‌کند که درخواست دوم فهرست آثار متصل از کش برمی‌گردد و پس از تغییر generation، کوئری و بررسی امضا دوباره اجرا می‌شوند.
- بررسی ایستا برای افزایش نسخه پایگاه داده به ۸ و افزودن دو ستون پیوست رسانه با `dbDelta` (بدون حذف داده‌های موجود).
- بررسی مسیرهای invalidation کش بعد از ایجاد، ابطال و انتقال مالکیت گواهی و پس از ذخیره/تغییر وضعیت گالری یا پروفایل.
- سنجش واقعی زمان پاسخ، تعداد کوئری‌ها و Lighthouse انجام نشده است؛ هر بهبود واقعی باید در staging سایت هدف اندازه‌گیری شود.

## قابلیت‌های جدید

- فرم صدور گواهی امکان انتخاب/بارگذاری تصویر اصلی اثر از پنجره رسانه وردپرس را دارد؛ فرمت‌های JPEG، PNG، WebP، GIF و AVIF در نسخه‌های سازگار تا ۲۵ مگابایت پذیرفته می‌شوند.
- شناسه گواهی از تولیدکننده تصادفی موجود با بررسی موجودنبودن و قید UNIQUE دیتابیس ساخته می‌شود. کد در پیام موفقیت و گواهی چاپی ارائه می‌شود.
- QR Code به‌صورت محلی در مرورگر تولید می‌شود و به نشانی اختصاصی استعلام همان کد اشاره می‌کند. تولید QR به شبکه یا API خارجی نیاز ندارد.
- payload امضاشده نسخه ۶ شامل ID رسانه و SHA-256 فایل اصلی است؛ verify() فایل جاری را مجدداً هش می‌کند و در صورت حذف یا تغییر فایل، اعتبار امضا را رد می‌کند.
- سازوکار payload canonical نسخه ۵ بدون تغییر برای گواهی‌های قبلی حفظ شده است؛ نسخه‌های امضای ۱ تا ۴ نیز هنوز شاخه‌های اعتبارسنجی جداگانه دارند.
- در صورت فعال‌بودن permalink، افزونه مسیر `/coa-verify/CODE/` را ثبت می‌کند؛ در حالت پیوند یکتای خاموش، از query URL استفاده می‌شود. کد خوش‌ساخت ولی ناشناخته پاسخ 404 می‌گیرد.

## آزمون‌های انجام‌شده در محیط محلی

- اجرای `php -l` روی تمام فایل‌های PHP افزونه با PHP 8.4.24.
- `node --check` روی فایل‌های JavaScript جدید.
- تولید ماتریس QR برای نمونه URL و رندر آزمایشی؛ رمزگشایی با OpenCV دقیقاً همان URL ورودی را بازگرداند.
- بررسی قواعد URL و regex کد یکتا، فیلدهای DB و مسیرهای signature schema 5/6.
- بررسی ساختار آرشیو ZIP.

## محدودیت‌ها و آزمون‌های لازم روی staging

- نصب کامل روی وردپرس واقعی، اجرای `dbDelta` روی پایگاه داده موجود، آزمایش رسانه وردپرس با نقش‌های محدود، Elementor و قالب سایت در مرورگر هنوز انجام نشده است.
- آزمون PHP 7.4 runtime در این محیط موجود نبود؛ هدر افزونه همچنان PHP 7.4 را اعلام می‌کند، پس باید روی PHP 7.4 واقعی یا CI مطابق آن بررسی شود.
- در سایت‌هایی با rewrite/cache خاص، پس از ارتقا در صورت 404 مسیر `/coa-verify/CODE/`، یک بار ذخیره تنظیمات «پیوندهای یکتا» و پاک‌سازی کش لازم است.
- فایل اصل اثر با هر استعلام گواهی نسخه ۶ مجدداً هش می‌شود تا تغییر محتوا تشخیص داده شود؛ برای فایل‌های حجیم و پرترافیک این کار I/O دیسک اضافه دارد. سقف اندازه تصویر ۲۵ مگابایت است.
- غیرفعال کردن نمایش تصویر در افزونه، URL اصلی رسانه وردپرس را خصوصی نمی‌کند؛ فایل‌های Media Library معمولاً مستقیماً قابل دسترسی‌اند. برای تصاویر محرمانه باید ذخیره‌سازی خصوصی مجزا پیاده‌سازی شود.
- QR/صفحه استعلام و هش فایل، به‌تنهایی اصالت فیزیکی اثر، انتساب حقوقی یا مالکیت اثر را اثبات نمی‌کنند.

# گزارش کنترل کیفیت — WP COA Pro 1.9.0

## قابلیت‌های جدید بررسی‌شده در سورس

- عنوان و توضیحات سئوی پویا برای پروفایل‌های منتشرشده، به همراه فیلدهای اختیاری عنوان و توضیح اختصاصی در پیشخوان.
- canonical و متادیتای Open Graph/Twitter در حالت جایگزین و فیلترهای یکپارچه‌سازی با Yoast SEO، Rank Math، SEOPress و AIOSEO.
- JSON-LD از نوع `ProfilePage` با موجودیت اصلی Person یا Organization و BreadcrumbList.
- مسیرهای تمیز پروفایل با rewrite rules و نگهداری مسیر query قدیمی؛ پاسخ 404 و noindex برای نامک عمومی ناموجود/منتشرنشده.
- نقشه سایت XML چندبخشی برای پروفایل‌های منتشرشده و افزودن نشانی آن به robots.txt.
- کش transient برای نتایج عمومی و تعداد پروفایل‌ها با افزایش نسل کش پس از ذخیره پروفایل.
- بارگذاری شرطی CSS و شاخص‌های ترکیبی برای فهرست پروفایل‌ها و آثار فعال متصل.

## آزمون‌های اجراشده

- اجرای `php -l` برای تمام فایل‌های PHP با PHP 8.4.24.
- بازبینی دستی نسخه‌بندی دیتابیس و تعریف `dbDelta` برای افزودن SEO title/description و شاخص‌های جدید، بدون حذف فیلدها یا جدول‌های قبلی.
- اجرای تست دود محلی با شبیه‌سازی APIهای منتخب وردپرس برای تأیید عنوان، توضیحات، canonical و خروجی JSON-LD پروفایل.
- اجرای تست سازگاری امضای محلی: سازگاری امضای v4 قدیمی، اتصال شناسه پروفایل در payload نسخه 5، اعتبارسنجی رکورد و تشخیص دست‌کاری.
- بررسی ایستا برای نسخه افزونه/پایگاه داده، فیلدهای SEO، قواعد sitemap، invalidation کش و بارگذاری شرطی CSS.
- بررسی دستی مسیرهای کنترل‌شده برای canonical، تغییر مسیر URL قدیمی، sitemap، robots.txt، حریم خصوصی و تولید JSON-LD.
- بررسی سلامت آرشیو ZIP و محتوای ترجمه‌ها هنگام بسته‌بندی.

## محدودیت‌ها و تست‌های لازم روی staging

- هیچ سایت وردپرسی واقعی با این نسخه اجرا نشده؛ بنابراین مهاجرت دیتابیس، rewrite rules در پیوند یکتاهای واقعی، محتوای XML در مرورگر، و ادغام واقعی با نسخه‌های نصب‌شده Yoast/Rank Math/SEOPress/AIOSEO هنوز تست انتها‌به‌انتها نشده‌اند.
- PHP 7.4 به‌صورت runtime در این محیط موجود نیست؛ حداقل نسخه PHP در سربرگ 7.4 باقی مانده، اما سازگاری باید روی محیط واقعی PHP 7.4 بررسی شود.
- امتیازهای Lighthouse، PageSpeed Insights، Core Web Vitals و زمان پاسخ سرور اندازه‌گیری نشده‌اند؛ بهبود سرعت در این بسته بر اساس کاهش بار CSS و کوئری‌های تکراری طراحی شده و باید با ابزارهای اندازه‌گیری در سایت هدف اعتبارسنجی شود.
- پیش از ارتقا در سایت عملیاتی از فایل‌ها و دیتابیس نسخه پشتیبان تهیه شود.
